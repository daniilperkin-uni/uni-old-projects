The facet promise

A count is a contract: the number shown for a value is exactly the number of rows you get after picking it.

  • Each facet counts itself out.
  • The date window never counts the date against itself.
  • Formats only count while uploads are selected; repositories only while a repo source is.

All counts come from one Criteria query — no N+1 per option.

  • Quality gates on every pull request — format, build, lint and tests per service, plus a secret scan and Docker builds in CI.
  • One Modulith, honest seams — the backend's modules talk through domain events, never through each other's internals.
  • The buddy is one agent, one loop — it searches while the model asks, then answers from the same conversation; every citation is a chunk it actually read.

BSEM — Annotation & Dataset Audit

A seminar team project on data-centric AI. Do annotators agree — and does talking about it help? 216 tweets, two annotators, one codebook and one expert: agreement before and after discussion (Bennett's S, Cohen's κ, Gwet's AC1), plus a 76-criterion audit of Microsoft COCO vs SA-1B.

Agreement before → after

metric   before   after
PA       0.870    0.981

AC1      0.840    0.978
kappa    0.321    0.885

All four metrics move the same way. What remains after discussion are 4 expert decisions out of 216 rows (1.9%).

What it shows

  • The prevalence paradox — with rare positives κ collapses (0.32) while Bennett's S stays high (0.74) on identical labels. The simulations show why: guessing alone reaches S = 0.81 at 5% prevalence, while κ stays at 0 for pure guessing at any prevalence.
  • Against the original labels — PA 91.7% (198/216), AC1 0.90 versus a trivial "never offensive" baseline of 0.89, κ 0.50: disagreement concentrates on the rare offensive cases, with a topical pattern (BLM missed, Elections 2020 over-labelled).
  • Dataset audit — COCO vs SA-1B on 76 criteria across planning, sourcing, ethics, quality assurance and adjudication: COCO wins on semantics (categories per object), SA-1B on boundary quality (94% of mask pairs > 90% IoU) but ships no categories at all.

A full-stack Todo web app: a Vue 3 + TypeScript SPA on a Spring Boot 4.1 REST API with MariaDB in Docker — and a trained ML classifier that sorts every todo title into work or private as it is saved.

The classifier — running in your browser

The backend loads model.pmml (a 38-token TF-IDF linear model, logit-normalized) through JPMML and classifies each todo on create and update — the statistics view splits by the resulting category. This widget runs the same model's arithmetic in JS, ported token-by-token from the PMML: tokenize → idf × coefficient per matched token → signed score → class. Try the chips, or type a title like team car and watch which side of the line it lands on.

What it does

  • Todos CRUD + assignment — description, LOW/MEDIUM/HIGH priority, assignees resolved server-side; validation failures come back as RFC 7807 ProblemDetail.
  • Kanban board in sync with the finished flag — finishing from the list or dragging a card to DONE keeps status and flag consistent; both write paths are pinned by tests.
  • Recurring todos — WEEKLY/MONTHLY with month-end clamping; finishing spawns exactly one successor, and a repeated DONE move never duplicates it.

PE1 Selection Wheel

A Swing wheel-of-fortune selector where the spin is real physics: drags and random spins decelerate at a constant −20 °/s² and land under the pointer on whichever animal the math picks. The wheel below is the app itself, ported — the deceleration, the section index and the stop conditions come straight from the project's pure Java classes.

Java 21Swing / AWTMavenJUnit 5 · AssertJJaCoCoGitHub Actions · xvfbEDT-safe

Live — drag the wheel and release to flick it, click it mid-spin to stop it dead, press Space/Enter (or the button) for a random spin at 180–360 °/s. The animation advances in the app's own 10 ms steps of SpinStep.compute, and the selection under the pointer is the same floor(n + angle % 360 / 24°) % n. Spin speed and direction, deceleration and landing are validated 1:1 against the Java classes — 8,892 generated test vectors, zero mismatches.

Architecture: three pure layers around a Swing shell

selectionwheel/
├─ WheelModel   state: items · angle · spin params
│               — zero Swing imports
├─ WheelMath    pure fns: section angle · [-360,360)
│               normalize · selection index · drag delta
├─ SpinStep     pure record: one 10 ms tick →
│               (delta°, new speed, stop?)
├─ TickMath     pure fns: pointer polygon geometry
├─ Wheel · Tick · SelectionWheel  Swing views
├─ WheelRenderer  paints into a BufferedImage
└─ MainWheel    JFrame · keyboard · inline result bar
// SpinStep.compute — the entire spin physics.
public static SpinStep compute(double currentSpeed, int direction,
        double deceleration, double dtSeconds) {
    double delta = direction * (currentSpeed * dtSeconds);
    double nextSpeed = currentSpeed + deceleration * dtSeconds;
    if (nextSpeed <= 0) { return new SpinStep(delta, 0, true); }
    return new SpinStep(delta, nextSpeed, false);
}

Everything a spin needs is derived from three lines of arithmetic: the landing angle is the sum of the per-tick deltas, the duration is v / 20 s, and the selection is a modulo. That is why the whole physics could be asserted headlessly — and why the widget above can replay it in a browser at a fixed 100 Hz, catching up with the wall clock in 10 ms steps.

Engineered, not just built

  • The wheel no longer rotates twice on resize — the base image used to bake in the rotation and have it applied again at paint, desyncing pointer and selection; the renderer is now rotation-independent (WheelPaintTest).
  • The pointer survives repaints — the tick polygon's scaling used to compound on every paint; geometry now returns a fresh, idempotent polygon (TickMathTest).
  • The sidebar keeps its width — selecting a longer item name used to re-lay-out the frame and make the wheel jump (MainWheelInfoPanelTest).
  • Font auto-sizing is a binary search — it replaced an O(n) re-rasterize loop and fixed a height-overflow edge on narrow sections.
  • No Thread.sleep, anywhere — the spin rides a javax.swing.Timer on the EDT, a detached wheel stops its timer, and the tests synchronize on CountDownLatch callbacks instead of sleeping (SelectionWheelIntegrationTest).

Coverage: pure layers 97–100 %, overall 62.6 % — the Swing views carry the remaining gap and there is no threshold gate yet. CI: every push runs ./mvnw -B verify under xvfb on JDK 21, the Swing tests need a display. Source: github.com/daniilperkin-uni/pe1_selection_wheel (public).
