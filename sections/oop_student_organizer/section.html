EInf Student Organizer

A JavaFX desktop app for the first semesters: modules with ECTS and status, deadline cards with overdue states, an ECTS-weighted GPA with charts — and a grade simulator that answers "what do I still need for 2,0?". One window, three tabs, CSV persistence, no database.

The Noten tab — where the math lives

All captures come from a headless capture run against a seeded demo home directory (tools/demo-data/, fictional modules) — the app's real user data never left its own folder.

Three tabs, one window

  • Module — cards per module with ECTS, semester and Leistung (Prüfungsnote or Studienleistung), searchable and filterable; module add/edit validated ("ECTS müssen größer als 0 sein.").
  • Fristen — Anmeldung / Abgabe / Klausur deadlines with the three-colour state model, done-marking, and an iCalendar (.ics) export of every deadline.
  • Noten — the ECTS-weighted average, passed/total ECTS, the progress pie, the grade chart, the Notensimulator and the per-semester dashboard.

Shape of the codebase

com.example.einf            (JPMS module)
├─ Main                   load/save · wiring · exit flush
├─ HomeController         one FXML, all @FXML refs
│   ├─ ModuleTabController      search · filters · cards · dialog
│   ├─ DeadlineTabController    states · done · ICS export
│   └─ GradesTabController      GPA · charts · Notensimulator
├─ Modul · Deadline · Semester · Leistung
│   (Pruefungsleistung · Studienleistung)
├─ LeistungsRechner · EctsFortschritt · SemesterStatistik
└─ SpeicherManager · IcsExporter

The tab logic was extracted from the former 674-line HomeController into a coordinator plus one controller per tab (674 → 189 lines), while the single FXML stayed untouched on purpose — no fx:include rewrite on a UI that deliberately has no FXML-loading test coverage. Persistence is equally deliberate: two semicolon-separated CSVs with custom escaping (\; / \n), a .bak copy before every overwrite, and a legacy four-column reader that still loads module files written before the split. The simulator math is pinned by its own test class, and the website widget is pinned against the same implementation.
