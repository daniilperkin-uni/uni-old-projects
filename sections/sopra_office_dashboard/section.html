SoPra Office Dashboard

A kiosk dashboard for the office — one full-screen 4K display rotating through calendar, parking, highscore, a combined overview and live weather, with an admin area behind it and a FallingCats easter egg on the side. Built as a university team project (Software-Praktikum): Spring Boot 4.1 multi-module backend, Vue 3 kiosk UI, MariaDB, Docker Compose.

The kiosk — interactive replay

Every frame is a real capture from the running stack at 3840×2160 — the kiosk renders one fixed 4K canvas and a Smart Scaler transforms it to fit whatever screen it runs on, so this is the layout as designed. The live display rotates on a configurable interval (15 s default), cuts between views with no crossfade and re-reads its config every 30 s — this replay does the same, just faster. Switch to Admin for the screens behind the glass; click the stage to zoom a frame.

Behind the glass: the admin area

Everything the kiosk shows is managed in a responsive Vue admin (/admin/*) — from a desktop or a phone, through the same REST API the display uses. The whole area sits behind a session login.

Under the hood: seven modules, one app

backend/ — Gradle 9 · Java 21 · Spring Boot 4.1.1
common/                   Mattermost client + shared plumbing
module-events/            Odoo XML-RPC → birthdays, anniversaries, probation
module-parking/           reservations + daily occupancy
module-highscore/         darts ELO + kicker standings
module-community-lunches/ events, options, votes, food catalog
module-config/            display + rotation settings
backend/                  runnable app · session security · Liquibase master
frontend/ — Vue 3.5 · Vite 7 · Pinia · Tailwind
features/    calendar · parking · highscore · community-lunch · dashboard · game
views/       DisplayView (the kiosk) · admin screens
composables/ useDisplayScaler · useViewRotation

One runnable jar, clean seams: every feature module owns its controllers, services, entities and changelog, and the schema is fully managed by Liquibase (ddl-auto=validate) — adding a module means registering it in settings.gradle, build.gradle and the master changelog, and applied changesets are never edited. Background work stays quiet: the events module caches Odoo and refreshes daily, and a 12:00 cron pushes upcoming birthdays, anniversaries and new lunch events into the team's Mattermost.

Tests & CI

Every push runs the full pipeline: backend ./gradlew build (compile · Checkstyle · 93 tests · boot jar) and frontend lint, format check, 63 Vitest tests and the production build on Node 22. The backend suite spans all seven modules — 91 run, the two @Disabled ones are the live-Odoo integration tests, kept runnable locally.

$ ./gradlew build      # backend — compile · Checkstyle · tests · boot jar
$ npm run lint && npm run format:check
$ npm run test && npm run build
$ docker compose up -d --build
  # MariaDB + API + kiosk in one command
