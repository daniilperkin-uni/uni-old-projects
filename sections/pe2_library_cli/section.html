The refactor: one monolith → five layers

LibraryCLI.java — 985 lines
├─ menu + I/O
├─ loan / return / fine math
├─ CSV parsing via String.split(",")
└─ reports
cli/      menu + Scanner I/O (the only I/O layer)
csv/      RFC-4180-subset parser · save on exit
manager/  CRUD per entity + reservations
service/  LoanService · ReportService (pure)
model/    Book · BookCopy · Customer · Reservation

Services never print — they throw typed exceptions and the CLI catches and renders them. The audited bugs from the original code are each pinned by a test: the loan guard order, return authorization, the naive CSV split, uncaught InputMismatchException, hardcoded fixture paths, plus deletion and startup guards.

What it does

  • Nine-option German menu — Bücher, Buchkopien, Kunden, Ausleihe, Rückgabe, Suche, Vormerkungen, Berichte, Beenden.
  • Loans on a real clock — 21-day loan period, then 0.50 € per overdue day, itemized on return.
  • FIFO reservations per ISBN — queue view and cancellation; the waiting list matters as soon as every copy of a title is out.
  • State that survives restarts — saved on clean exit, reloaded on next start; quoted CSV fields and umlauts handled; corrupt saved data refuses to load instead of crashing.
