PE1 Selection Wheel

A Swing wheel-of-fortune selector where the spin is real physics: drags and random spins decelerate at a constant −20 °/s² and land under the pointer on whichever animal the math picks. The wheel below is the app itself, ported — the deceleration, the section index and the stop conditions come straight from the project's pure Java classes.

Live — drag the wheel and release to flick it, click it mid-spin to stop it dead, press Space/Enter (or the button) for a random spin at 180–360 °/s. The animation advances in the app's own 10 ms steps of SpinStep.compute, and the selection under the pointer is the same floor(n + angle % 360 / 24°) % n. Spin speed and direction, deceleration and landing are validated 1:1 against the Java classes — 8,892 generated test vectors, zero mismatches.

Painting a wheel without a display

The renderer was extracted so it can paint into a BufferedImage with no window involved — the images below come straight from WheelRenderer.render(model, 1200, 1200). It is deliberately rotation-independent: the model's angle is applied by the component at paint time, so the cached image stays valid while the wheel turns.

Architecture: three pure layers around a Swing shell

selectionwheel/
├─ WheelModel   state: items · angle · spin params
│               — zero Swing imports
├─ WheelMath    pure fns: section angle · [-360,360)
│               normalize · selection index · drag delta
├─ SpinStep     pure record: one 10 ms tick →
│               (delta°, new speed, stop?)
├─ TickMath     pure fns: pointer polygon geometry
├─ Wheel · Tick · SelectionWheel  Swing views
├─ WheelRenderer  paints into a BufferedImage
└─ MainWheel    JFrame · keyboard · inline result bar
// SpinStep.compute — the entire spin physics.
public static SpinStep compute(double currentSpeed, int direction,
        double deceleration, double dtSeconds) {
    double delta = direction * (currentSpeed * dtSeconds);
    double nextSpeed = currentSpeed + deceleration * dtSeconds;
    if (nextSpeed <= 0) { return new SpinStep(delta, 0, true); }
    return new SpinStep(delta, nextSpeed, false);
}

Everything a spin needs is derived from three lines of arithmetic: the landing angle is the sum of the per-tick deltas, the duration is v / 20 s, and the selection is a modulo. That is why the whole physics could be asserted headlessly — and why the widget above can replay it in a browser at a fixed 100 Hz, catching up with the wall clock in 10 ms steps.

Engineered, not just built

  • The wheel no longer rotates twice on resize — the base image used to bake in the rotation and have it applied again at paint, desyncing pointer and selection; the renderer is now rotation-independent (WheelPaintTest).
  • The pointer survives repaints — the tick polygon's scaling used to compound on every paint; geometry now returns a fresh, idempotent polygon (TickMathTest).
  • The sidebar keeps its width — selecting a longer item name used to re-lay-out the frame and make the wheel jump (MainWheelInfoPanelTest).
  • Font auto-sizing is a binary search — it replaced an O(n) re-rasterize loop and fixed a height-overflow edge on narrow sections.
  • No Thread.sleep, anywhere — the spin rides a javax.swing.Timer on the EDT, a detached wheel stops its timer, and the tests synchronize on CountDownLatch callbacks instead of sleeping (SelectionWheelIntegrationTest).
