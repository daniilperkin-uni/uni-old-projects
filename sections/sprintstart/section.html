SprintStart

An AI-assisted onboarding platform: connect a GitHub organization, ingest every pull request, issue, file and commit, upload what lives outside it — and get a knowledge base that answers with citations, an onboarding buddy, and a PM view of what the team knows. My current university team project (StuPro 2026): twelve people, ten two-week sprints, releases v0.1.0 → v0.10.0.

Under the hood

Three services, one origin

In development everything is reverse-proxied through the frontend's origin — /api and /v1 to the backend, /auth to Keycloak — so there is no CORS sprawl and no second login. The whole stack is one docker compose up away.

No filter lives in component state: a click rewrites the query string and the page re-reads it — links, refresh and the back button work for free, and a broken link is discarded, never an error.

The facet promise

A count is a contract: the number shown for a value is exactly the number of rows you get after picking it.

  • Each facet counts itself out.
  • The date window never counts the date against itself.
  • Formats only count while uploads are selected; repositories only while a repo source is.

All counts come from one Criteria query — no N+1 per option.

  • Quality gates on every pull request — format, build, lint and tests per service, plus a secret scan and Docker builds in CI.
  • One Modulith, honest seams — the backend's modules talk through domain events, never through each other's internals.
  • The buddy is one agent, one loop — it searches while the model asks, then answers from the same conversation; every citation is a chunk it actually read.
